# Проверочный лист безопасности бизнес-систем PropDevelopment

## Обоснование выбора разделов

В проверочный лист включены все пять разделов шаблона. Ниже — приоритеты и аргументация.

### Приоритет 1 — II. Безопасность данных
Прямая связь с главной проблемой компании: несколько точек регистрации клиентов без координации, отсутствие контроля внутренних потоков данных, системы обработки данных без ограничений на доступ. Подтверждённый инцидент: клиенты видят чужие ФИО в личном кабинете. Без покрытия этого раздела аудит лишён смысла.

### Приоритет 2 — I. Управление доступом
Партнёр одной управляющей компании может просматривать и изменять данные клиентов другой — прямое нарушение принципа минимальных привилегий и изоляции данных. Множество точек входа (витрина продаж, онлайн-тур, онлайн-сделка, мобильное приложение ЖКУ) при единственном специалисте по ИБ создают риск неконтролируемого расширения прав. Изменения в составе руководителей нарушили порядок информирования ИБ — вероятно, нарушена и процедура отзыва прав.

### Приоритет 3 — IV. Управление инцидентами
Инцидент с данными клиентов был обнаружен по жалобам пользователей, а не системами мониторинга. Утечка данных у конкурента активно обсуждается в СМИ. Единственный специалист по ИБ — очевидный bottleneck при реагировании. Всё это указывает на отсутствие зрелых процессов управления инцидентами.

### Приоритет 4 — III. Защита инфраструктуры
Гибридная инфраструктура (собственный ЦОД + арендованные облачные ресурсы) расширяет периметр атаки. Интеграции с госорганами через СМЭВ и API управляющих компаний без единых политик безопасности создают дополнительные векторы. Межсетевой экран для внешних пользователей зафиксирован, но достаточность сегментации не подтверждена.

### Приоритет 5 — V. Специфические аспекты
Мобильное приложение для собственников управляет устройствами умного дома, включая замки квартир — это требует проверки MDM и политик удалённого доступа. Наличие собственного ЦОД делает актуальными вопросы физической безопасности.
